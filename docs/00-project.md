# Паспорт проекта YogaVibe

## Назначение и происхождение

YogaVibe — собственный проект, веб-платформа для поиска наставников по йоге и записи на занятия. Проект помогает пользователю подобрать ментора по городу, направлению и стоимости, оформить запись и хранить личные заметки о практике. Это существующее приложение со своей предметной областью, не форк учебного примера.

Репозиторий: https://github.com/wixucys/yogavibe.
Согласование выбора и плана: [issue product №1](https://github.com/wixucys/yogavibe/issues/1).
Исходная ревизия до ЛР1: `7ac2104a`. Работа ведётся в ветке `lab-1`.

## Пользователи и роли

| Роль | Назначение |
| --- | --- |
| Пользователь (`user`) | Ищет ментора, записывается, отменяет свои записи, ведёт заметки и профиль |
| Ментор (`mentor`) | Редактирует свой профиль, просматривает записи клиентов, завершает занятия |
| Администратор (`admin`) | Управляет пользователями, ролями и менторами, просматривает сводку |

Пять предметных сущностей: `User` — учётная запись и профиль; `Mentor` — профиль наставника; `Booking` — запись на занятие; `Note` — личная заметка; `FileAttachment` — вложение. `RefreshToken` служит для авторизации и не считается отдельной предметной сущностью. Все модели находятся в `backend/app/models_db.py`.

Три основные функции: поиск и выбор ментора; создание и отмена бронирования; ведение заметок.

### Хранение данных и внешние сервисы

API сохраняет SQLite в `/app/data/yogavibe.db` (том `backend_data`), вложения локального провайдера — в `/app/app/data/uploads` (том `backend_uploads`). При обычном `docker compose down` данные сохраняются. Схема создаётся через `Base.metadata.create_all`; миграций пока нет.

Браузер обращается к Nginx на порту 80; Nginx передаёт `/api/` в backend:8000, остальные запросы — frontend:8080. Frontend в итоговом образе — статические файлы, npm в нём отсутствует.

MinIO использует S3 API на 9000 и консоль на 9001, хранит объекты в `minio_data`; в базовом сценарии не запускается. Интеграция погоды требует ключ OpenWeather и необязательна для основных функций. Очередей сообщений и платёжных сервисов нет.

### Конфигурация

`.env.example` содержит публичные настройки локального запуска. Пользователь копирует его в `.env`; Compose передаёт нужные значения в backend. `SECRET_KEY` обязателен, `DATABASE_URL` задаёт SQLite, `FILE_STORAGE_PROVIDER` выбирает `local` или `s3`. `STORAGE_PUBLIC_BASE_URL` задаёт адрес скачивания файлов через внешний Nginx. Ключи MinIO, bootstrap администратора и OpenWeather передаются явно.

При локальном запуске Python `config.py` также читает `backend/.env`, `backend/app/.env` и, в тестовом режиме, `backend/.env.test`. Эти файлы исключены из Git и Docker-контекста. Настройки `REACT_APP_*` считываются при сборке React; основной клиент использует относительный `/api`.

### Первые наблюдения

1. `create_all` не обеспечивает изменение существующей схемы: нужен механизм миграций — [№2](https://github.com/wixucys/yogavibe/issues/2).
2. Корректность одновременной записи двух клиентов требует конкурентного теста; дефект пока не утверждается — [№3](https://github.com/wixucys/yogavibe/issues/3).
3. База и вложения сохраняются раздельно, процедура согласованной резервной копии отсутствует — [№4](https://github.com/wixucys/yogavibe/issues/4).
4. Недоступность образов MinIO блокировала исходный запуск; основной сценарий теперь локальный, S3-профиль требует отдельной проверки — [№5](https://github.com/wixucys/yogavibe/issues/5).

## Выполнимость и план

Проект выполним за семестр при ограничении объёма существующими пользовательскими сценариями. Базовая реализация уже есть; основное время потребуется на формализацию требований, проверку ошибок, архитектурные решения и выпуск.

| Риск | Вероятность | Последствия | Снижение |
| --- | --- | --- | --- |
| Старый react-scripts и сложное дерево npm | Средняя | Несовместимость пакетов, затраты на обновление | Использовать lock-файл, обновлять отдельно с тестами |
| SQLite и конкурентные бронирования | Средняя | Конфликтующие записи или блокировки | Определить инварианты, добавить конкурентные тесты и транзакционную защиту |
| Нет миграций | Высокая при изменении схемы | Потеря совместимости существующей БД | ADR и миграции до изменения моделей; резервная копия |
| Недоступные образы MinIO | Уже проявился | Не запускается S3-профиль | Основной local-провайдер, восстановление S3 отдельной задачей |
| Один участник и ограниченное время | Средняя | Срыв сроков | План 44 часа + резерв 8 часов, не расширять функциональность до завершения обязательного объёма |
| Недоступность преподавателя для согласования | Средняя | Задержка закрытия ЛР1 | Открытый product с конкретными пунктами согласования |
| Отсутствие ключа/квоты OpenWeather | Средняя | Нет прогноза погоды | Погода вне обязательного сценария; тесты с подменой API |
| Нет LICENSE по решению автора | Высокая для формальной приёмки | Замечание по задаче 2 | Явно согласовать исключение в product |
| Отсутствие проверенной резервной копии | Средняя | Невосстановимые данные | Проверка восстановления в ЛР6 до выпуска |

## Журнал запуска

Хотя проект не является форком, найденные проблемы зафиксированы для воспроизводимости.

| Проблема | Решение |
| --- | --- |
| Compose не передавал обязательный `SECRET_KEY` | Добавлены `.env.example` и явное обязательное значение |
| Параметры S3 отсутствовали в окружении backend | Добавлена явная передача bucket и ключей |
| Локальные `.env` могли попадать внутрь backend-образа | Исключены вложенные env-файлы и базы из Docker-контекста |
| Docker использовал `npm install` | Заменён на `npm ci`, существующий lock сохранён в Git |
| Линтер искал только JS/JSX и не имел конфигурации | Добавлен ESLint для TS/TSX, устранены замечания |
| Инструкция запускала npm в итоговом Nginx-образе | Тесты frontend запускаются в builder-образе |
| MinIO недоступен из реестров | Основной local-провайдер с постоянным томом, необязательный профиль S3 и issue №5 |
| Несколько worker одновременно создавали бы таблицы новой SQLite | Для локального запуска установлен один worker |
| CI содержал неподдерживаемый `services.minio.command` | Ненужный сервис удалён: тесты используют local-провайдер и S3 mock |

Подробный протокол фактических проверок приведён в корневом README.
